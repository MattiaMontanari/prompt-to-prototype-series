Lecture 01 · Web publishing

A website, in more than one language

Follow the path from Markdown and templates to a multilingual static website.

InstructorMattia Montanari
Class date24 November 2025
SeriesUniversity of Oxford
IT Services · Digital Capabilities

A static website starts with files you can read and edit. This class explored migrating a personal site to a Hugo template and organising content in English and Italian.

Separate the words from the layout

Hugo combines content, usually written in Markdown, with templates that describe the presentation. A build produces HTML files that a static host can serve.

This separation is useful during a template migration. The article’s words can stay the same while the navigation, typography and page structure change. The migration still needs a review of image paths, menus and links.

A static site

The published pages are built ahead of time. Reading an article does not require a Python server or a model call.

Two languages, one site

The class notes use separate content directories, content/en and content/it, with a shared Hugo configuration. Each language has its own label and ordering weight.

[languages]
  [languages.en]
    languageName = "English"
    weight = 1
    contentDir = "content/en"
  [languages.it]
    languageName = "Italiano"
    weight = 2
    contentDir = "content/it"

The session explored automatically generating multilingual content. Language configuration itself does not translate prose: translations must still be generated or written, reviewed and stored as content.

From edit to publication

Use hugo server -D to preview changes, including drafts. Use hugo --minify to produce the static output for publication. The public/ directory is the build output in a standard Hugo site.

When migrating a theme, start with one representative page. Check its links, language switch, images and layout at a narrow screen width before applying the theme across the site.

The useful boundary

Content, presentation and publication are separate jobs. Keeping that boundary clear makes it easier to change a theme, add a language, or move a site to a different static host.
