Lecture 02 · Agents

What makes an LLM an agent?

Explore how tools, a decision loop and conversation memory extend a language model.

InstructorMattia Montanari
Class date1 December 2025
SeriesUniversity of Oxford
IT Services · Digital Capabilities

A language model can answer a prompt. An agent adds a way to act on the world and use the results in its next decision. This class built a small Python example with file tools and conversation memory.

A model inside a loop

The application sends the conversation and tool definitions to Claude. The model can return a reply or request a tool. When a tool is requested, the Python program executes it and adds the result to the conversation before asking the model again.

The important connection is the return path: a tool result becomes new input to the model. One user request can therefore involve several model calls and several actions.

Who runs the tool?

The model requests a named operation. The surrounding Python application executes it and returns the result.

Two small tools

list_directory returns the items in a directory. read_file returns the text in a file. Their schemas describe the inputs the model can supply.

In the repository implementation, execute_tool() dispatches a tool name to one of these functions. If a file is missing, the tool returns an error message that can become part of the conversation.

if tool_name == "list_directory":
    return self.list_directory(tool_input.get("path", "."))
elif tool_name == "read_file":
    return self.read_file(tool_input["file_path"])

Memory is conversation history

The example stores user messages, assistant responses and tool results in a Python list. Each model call receives that history. The “Clear Memory” action empties the list and starts a fresh conversation.

This memory lasts while that agent instance is running. The code does not save it to disk, so restarting the application does not restore earlier conversations.

A stopping condition

An end_turn response ends the loop. The code also limits each request to ten iterations.

Inspect the implementation

The repository includes the agent code, a Flask server and a browser interface. The hosted lecture is a static explanation; the Python demo is a separate application.

A useful extension is to add one tool with a clear input schema and a focused job. Consider what information the model will need, what the tool returns, and how an unsuccessful call should be represented.

Observe the whole system

To understand an agent, inspect more than its final answer. Follow its tool requests, the results it receives, the history it keeps, and the condition that stops the loop.
